## Structure for PERFORMANCE.md

1. TITLE + one-paragraph executive summary: BoABot is an Albanian RAG customer-service chatbot (voice/call-center) with a /turn streaming endpoint; the performance work from Aug 2026 was driven by a 2,500 ms first-token target and a 1.5 s / 2.5 s voice first-audio target.

2. HOW IT WAS (THE BASELINE) — the "before" state with hard numbers:
   - Baseline /turn: first SSE p50 1,856 ms / p95 2,343; first token p50 4,724 / p95 8,062; done p50 6,209 / p95 9,707 (warm process). Cold start first request: first SSE 6,008 ms, first token 10,046 ms, done 11,322 ms.
   - Root causes identified: a full tool-decision completion (~4,471 ms p50) before the first SSE event, an unconditional rewrite model call (~1,412 ms) every turn, 2 embedding encodes/turn, new pgvector connection per turn, no warmup.

3. WHAT WAS DONE TO IMPROVE IT — the key metric, by phase, each with before/after numbers:
   - PHASE 1 (shipped): removed tool-calling from the critical path (first SSE 1,856 -> ~141-152 ms, ~92% cut; removed ~4.5 s of pre-stream model round-trip); conditional needs_rewrite() heuristic (rewrite paid only on elliptical/history turns; n=40 confirmation: rewrite off 0.400 vs on 0.725 retrieval, elliptical 0.000 -> 0.700); connection pooling (~12 ms/turn); startup warmup (~5.8 s saved on first request); embedding reuse when byte-identical (2 encodes -> 1, 100% hit ratio, no quality loss). Eval unchanged: RegArt@1 0.550, RegDoc@1 0.800.
   - PHASE 2 (shipped + measured): prompt caching — split system prompt so invariant instruction is a stable cacheable prefix + OpenRouter session_id sticky routing; cache hits 50% -> 90%, cached tokens 50,432 -> 104,448. Provider TTFT N=100 deepseek-v4-flash: p50 361 ms but p99 11,465 / max 14,045 (bimodal: 68% fast, ~32% long tail) — this external tail, not in-code overhead, is the real enemy. k-sweep (3/5/8): no clean latency win, eval unchanged, k=5 kept. System-prompt trim: 74 tokens saved but citations 14 -> 12, NOT shipped. Model comparison: gemini-3.1-flash-lite TTFT p50 629 / p99 1,137 (tight tail, 193 tok/s) vs deepseek p50 361 / p99 11,465 (20.6 tok/s) — Gemini recommended for voice; default NOT switched.
   - PHASE 3 (measured N=100): full /turn tables in phase3_analysis.txt — DeepSeek empty: first token p50 4,912 / p99 22,664, first sentence p50 6,554, done p50 8,848; Gemini empty: first token p50 844 / p99 10,608, first sentence p50 1,062, done p50 1,982; Gemini history first sentence p50 1,049, first-audio (first sentence + 300 ms TTS) p50 1,349 / p95 2,301. Cache isolation: cache on p50 4,197 vs off p50 4,512, p99 savings 8,449 ms. Voice budget: DeepSeek FAILS 1.5 s and 2.5 s targets; Gemini PASSES 2.5 s on history mode. Quality: numeric_grounded and citations hold for both models; no eval regression.
